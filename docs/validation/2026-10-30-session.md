# Sessão persistente de uma hora

Identity emite JWT com exp - iat = 3600 e expiresIn 3600. Identity e Gateway aceitam idade máxima de uma hora. O prazo da reserva de vaga (900 segundos) e os limites de tentativas de login não mudam.

O frontend salva token, dados públicos do usuário e expiresAt em eventhub.session.v1 no localStorage. Ao restaurar, confere estrutura, identidade e prazo contra o exp do JWT; os serviços verificam a assinatura. Recarregar/reabrir não estende a hora original. Cache inválido ou vencido é eliminado. Caso o navegador bloqueie armazenamento, a sessão da aba continua em memória.

Sair remove a sessão persistida e desconecta outras abas da mesma origem. Expiração também limpa o cache, inclusive após a aba voltar de suspensão. “Lembrar de mim” continua sendo preferência para o e-mail do próximo acesso, independente da persistência da sessão. Nenhuma senha é salva. JWTs copiados permanecem válidos até expirar; revogação centralizada não foi adicionada.

Validação concluída: build TypeScript/Vite aprovado, nove testes unitários de Identity/Gateway e oito testes de navegador aprovados. Token com 45 minutos foi aceito e idade acima de uma hora foi rejeitada. Login foi restaurado após reload e novo contexto com armazenamento salvo, com prazo preservado; saída sincronizada entre abas e expiração por relógio simulado também passaram. Fluxos cobrem participante e organização.

```powershell
npm --prefix gateway test
npm --prefix services/identity test
npm --prefix frontend run test:e2e
```
